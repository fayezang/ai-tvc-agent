# 0002 · 项目首次进入的入口固定为两个

- 状态：已采纳
- 日期：2026-08-30
- 决策者：fayezang

## 背景

启动包《用户流程补全与强制规则 · 项目开始与恢复》原文要求：

> 项目首次进入显示「从 Brief 开始」「导入已有脚本」「打开已有项目」三个入口。

代码中 `src/renderer/src/components/start-screen.tsx` 只实现了两个，缺「导入已有脚本」。

## 决策

**移除「导入已有脚本」入口，不再实现。** 首次进入固定为两个入口：

1. 从 Brief 开始
2. 打开已有项目

## 理由

脚本必须经由 `Brief → 创意 → 脚本` 链路产生，才能保证以下信息具备完整来源与版本谱系：

- 镜头编号的唯一性与顺序
- 每镜时长，且总和严格等于项目时长
- 英文图像 Prompt 与 Audio/SFX Prompt
- VO 原文
- 该脚本派生自哪一条创意方向、哪一份 Brief

直接导入的外部脚本无法满足这些约束。若允许导入，系统要么拒绝大部分真实输入，要么用 AI 补全缺失字段——后者等于凭空创造用户没写过的内容，与「脚本是唯一事实来源」直接冲突。

外部脚本仍可作为素材粘贴进 Brief，由 AI 在复述与创意阶段消化。这保留了复用已有内容的能力，同时不破坏版本谱系。

## 影响

- `start-screen.tsx` 维持现状，不新增入口
- 《现成能力调用规范 v2》§2.2 已同步移除该入口
- 完成度审计中「三入口缺一个」不再计为缺口
